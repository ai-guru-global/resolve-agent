模块以 `engine.py` 中的 `SyncEngine` 为唯一对外入口（由 `__init__.py` 暴露），协调配置加载、变更检测、双向/单向同步、引导建立基线以及校对任务生成；CLI (`cli.py`) 通过 `argparse` 子命令 `sync/watch/proofread/glossary/review` 调用引擎，并负责将结果打印到 stdout。

内部按职责分层：
- 数据模型层 (`models.py`)：全部使用 Pydantic v2 `BaseModel` 定义配置 (`SyncConfig`/`SyncPair`/`SyncDefaults`/`TranslatorSettings`/`ProofreadSettings`)、持久化结构 (`SyncStateFile`/`ReviewQueue`/`TranslationMemoryFile`/`GlossaryFile`) 及运行时对象 (`SyncSnapshot`/`ReviewItem`/`TranslationMemoryEntry`)，并通过 `model_rebuild` 解决循环引用。
- 格式处理器层 (`processors.py`)：定义抽象基类 `DocumentProcessor`，并提供 `MarkdownProcessor`、`LatexProcessor`、`TextProcessor` 三种实现，统一暴露 `translate`/`structure_signature`/`extract_text`/`segments` 四个方法，由 `get_processor(file_type)` 分发；所有处理器在翻译前用正则保护代码块、链接、数学公式等不可译片段，保证结构签名可用于冲突检测。
- 翻译管线 (`engine.py` 内 `TranslationPipeline` + `TranslationMemory`)：按 memory → command 的顺序尝试翻译，外部 translator 通过 `subprocess` 调用用户配置的 shell 命令并以 JSON 交换 payload，结果经术语表替换后写回 YAML 格式的翻译记忆库。
- 术语管理 (`glossary.py` 中 `GlossaryManager`)：独立维护 YAML 术语文件，支持增删查、别名匹配与术语一致性检查。
- 状态与持久化：`SyncEngine` 在初始化时从 YAML/JSON 加载 glossary、translation-memory、`.sync-state.json` 与 `review-queue.yaml`，并在每次同步/校对后落盘；冲突检测依赖对源/目标文本做 sha256 哈希并与上次快照比较。

依赖方向单向：`cli → engine → {glossary, processors, models}`，处理器不反向依赖引擎，仅通过回调函数接收逐段翻译。
