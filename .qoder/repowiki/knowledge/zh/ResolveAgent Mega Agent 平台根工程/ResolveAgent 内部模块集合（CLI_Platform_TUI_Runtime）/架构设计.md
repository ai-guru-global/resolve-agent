internal/ 按职责划分为四个并列子包：cli 通过 Cobra/Viper 暴露 agent/skill/workflow/rag/corpus 等子命令并调用后端 HTTP API；platform 提供 Agent、Skill、Workflow 的平台级领域模型与编排逻辑（当前以 doc.go 占位，表明该层为后续业务实现预留）；tui 基于 bubbletea/lipgloss 实现交互式 TUI，复用 cli 的客户端能力渲染仪表盘、Agent 列表与工作流视图；runtime 仅含说明文档，标记运行时相关代码的位置。各子包之间保持解耦：cli 与 tui 作为面向用户的入口分别依赖 platform 的业务抽象与外部服务，platform 不反向引用 cli/tui，形成单向依赖关系。
