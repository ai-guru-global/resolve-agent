模块以 `protocol.py` 中定义的 `SelectorProtocol`（`route` + `get_strategy_info`）为统一接口边界，所有实现均通过结构子类型满足该协议。
- 核心编排：`selector.IntelligentSelector` 维护 `strategy` 映射（`llm` / `rule` / `hybrid`），在 `route()` 中依次执行缓存命中 → 可选上下文增强 → 策略分派 → 审计记录，并通过 `_get_strategy` 懒加载 `strategies/` 下的具体策略实例。
- 策略层：`strategies/hybrid_strategy.py`、`strategies/llm_strategy.py`、`strategies/rule_strategy.py` 各自实现 `decide(input_text, agent_id, context)`，分别走 LLM 分类、正则规则匹配与“规则优先 + LLM 兜底”的混合路径。
- 意图与路由：`intent.IntentAnalyzer` 基于预编译的正则与关键词对输入打分并输出 `IntentClassification`；`router.RouteDecider` 将意图映射到最终 `RouteDecision`（workflow→fta、skill→skill、rag→rag、code_analysis→code_analysis、direct→direct），并根据置信度阈值与 code_context 做降级调整。
- 上下文增强：`context_enricher.ContextEnricher` 并行查询 skill/workflow/RAG 注册表、提取对话历史、检测代码片段与语言，产出 `EnrichedContext`，并在重试时保留 `resilient_feedback`。
- 弹性路由：`resilient_selector.ResilientSelector` 包装 `IntelligentSelector`，按优先级 `[skill → rag → fta → code_analysis]` 循环重试，失败后由 `ReEnricher` 增量注入错误类型偏好，并使用 `resolveagent.resilience.CircuitBreaker` 做熔断保护；还提供带用户澄清回路的 `route_and_execute_with_clarification` 与可插拔的 `AdaptiveWeightAdjuster`。
- 适配器：`hook_selector.HookSelectorAdapter` 与 `skill_selector.SkillSelectorAdapter` 将内部路由能力暴露为 Hook 管线与 Skill 调用形式，二者都实现 `SelectorProtocol`。
- 横切关注点：`cache.RouteDecisionCache`（TTL+LRU，支持 instance/global 双作用域）、`audit.DecisionAuditLogger`（异步队列写入）、`__init__.py` 通过 `__getattr__` 延迟导入避免循环依赖。
依赖方向：`resilient_selector` → `selector` → `strategies` / `intent` / `router` / `context_enricher` / `cache` / `audit`；适配器与协议位于顶层，不反向依赖具体策略。
