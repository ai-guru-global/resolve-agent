模块以 `manifest.py` 中的 Pydantic 模型（`SkillManifest`、`SkillParameter`、`ScenarioConfig`、`TroubleshootingStep`）定义技能的元数据契约，并通过 YAML 清单驱动；`loader.py` 的 `SkillLoader` 按清单解析 `entry_point`（module:func），用 `importlib` 动态导入并缓存为 `LoadedSkill`；`executor.py` 的 `SkillExecutor` 是统一入口，先按 manifest 校验输入/输出，再根据 `skill_type` 路由到 `SCENARIO` 走 `troubleshoot.py` 的 `TroubleshootingEngine`（顺序执行步骤、条件分支、汇总四要素 `StructuredSolution`），否则按 `execution_mode`（direct/sandbox）选择直接调用或 `sandbox.py` 的 `SandboxExecutor` 子进程隔离执行（支持 python/bash/javascript，通过 `resource.setrlimit` 限制 CPU/内存/文件描述符，超时 kill）。`solution.py` 集中定义排障产物模型并提供 Markdown 渲染。`builtin/` 子包提供可直接作为 skill 使用的实现：`code_exec.py`（基于 `SandboxExecutor` 的多语言执行）、`file_ops.py`（白名单目录 + 大小限制的文件读写）、`web_search.py`（Bing/Google/Searx/DuckDuckGo 多后端）、`selector_skill.py`（桥接上层 `IntelligentSelector`）。依赖方向单向：builtin → executor/loader → manifest/sandbox；executor ↔ troubleshoot 双向仅通过 `SkillResult`/`StructuredSolution` 解耦。
