模块以 `runner.HookRunner` 为核心编排器：通过注入的 `HookClient`（来自 `resolveagent.store.hook_client`）拉取 Go 平台注册的 Hook 定义，按 `execution_order` 排序并依次执行；每个 Hook 由已注册的本地 handler（`register_handler`）处理，handler 接收 `HookContext` 并返回 `HookResult`，pre-hook 的 `modified_data` 会回写到 `ctx.input_data`、post-hook 回写到 `ctx.output_data`，从而实现链式数据传递，且可通过 `skip_remaining` 短路后续 Hook。

- `models.py` 定义跨层共享的 `HookContext`/`HookResult` dataclass。
- `selector_handlers.py` 提供三个内置 handler（意图分析、决策审计、置信度覆盖），通过 `__init__.py` 的 `__getattr__` 懒加载以避免启动时依赖 `resolveagent.selector.intent`。
- `memory_client.py` 实现与真实 `HookClient` 同签名的 `InMemoryHookClient`，用于测试与开发环境替代 Go 后端。
- `patterns.py` 独立提供同步版 `HookChain`（pre→execute→post→feedback）作为“Loop Engineering”参考模式，与异步 `HookRunner` 并行存在。

依赖方向：`runner` → `models` + `store.hook_client`（仅 TYPE_CHECKING 导入）；`selector_handlers` → `hooks.models` + `selector.intent`（运行时懒导入）；`memory_client` → `store.hook_client` 类型；包对外仅暴露 `HookContext`、`HookResult`、`HookRunner`、`InMemoryHookClient` 及三个 selector handler。
