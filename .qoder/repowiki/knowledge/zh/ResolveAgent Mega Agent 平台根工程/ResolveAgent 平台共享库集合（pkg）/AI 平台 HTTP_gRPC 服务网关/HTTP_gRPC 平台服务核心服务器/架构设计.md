模块以 `server.go` 中的 `Server` 结构体为唯一入口，通过 `New()` 根据配置选择 PostgreSQL 或内存实现的各 Registry（Agent/Skill/Workflow/RAG/Hook/Memory/Solution/CallGraph/Traffic），并初始化 gRPC server（含 health check 与 reflection）及带超时配置的 `http.Server`。
- 路由层：`router.go` 集中注册所有 `/api/v1/*` REST 路径到对应 handler 方法，健康检查同时暴露 `/healthz` 与 `/api/v1/health`。
- 处理器层：每个业务域独立文件（agent_handlers、skill_handlers、workflow_handlers、rag_handlers、memory_handlers、solution_handler、callgraph_handlers、traffic_handlers、fta_handlers、hook_handlers、analysis_handlers、corpus_handler、model_handlers、config_handlers、system_handlers、runtime_client.go），仅依赖顶层 Server 注入的 Registry 与 RuntimeClient。
- 中间件层：`middleware/` 提供可组合的 HTTP 中间件——`auth.go` 支持网关头、JWT(HS256)与 API Key 三种认证方式并将 `AuthContext` 写入 context；`logging.go` 记录请求耗时与状态码；`telemetry.go`、`tracing.go` 负责指标与链路追踪。
- 通用设施：`response.go` 统一 JSON 响应封装，`error_mapping.go` 将 Python 运行时错误码映射为 Go `errors.Code`，供处理器统一错误处理。
- 依赖方向：handlers → registry/runtime → 存储后端；middleware 横向横切；Server 作为装配中心不直接持有业务逻辑。
