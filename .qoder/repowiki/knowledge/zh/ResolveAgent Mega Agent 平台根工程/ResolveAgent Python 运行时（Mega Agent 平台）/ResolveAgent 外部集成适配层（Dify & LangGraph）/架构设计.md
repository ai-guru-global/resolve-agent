模块按目标框架划分为两个并列子包：
- `dify/`：通过 `tools.py` 中的 `FTAAnalyzerTool`、`CodeDiagnosisTool` 等类暴露 `invoke(tool_parameters)` 接口，供 Dify 插件系统调用；每个工具内部优先走本地 ResolveAgent FTA/代码解析引擎（`resolveagent.fta.*`、`resolveagent.code_analysis.parsers.factory`），失败时回退到通过 `httpx` 调用远端 `/api/v1/fta/analyze` 的 REST API，配置来自 `RESOLVEAGENT_ENDPOINT` / `RESOLVEAGENT_API_KEY` 环境变量。
- `langgraph/`：`node.py` 定义 `ResolveAgentNode`（包装任意带 `reply` 方法的 Agent 作为 LangGraph 节点）和 `SkillExecutorNode`（通过 `SkillLoader` + `SkillExecutor` 执行命名 skill）；`builder.py` 的 `DiagnosisWorkflowBuilder` 提供预置图模板（triage→diagnose→resolve 三阶段、FTA 专注流程），并返回 `DiagnosisGraph` 统一封装执行——运行时检测 `langgraph` 是否安装，若可用则用 `StateGraph` 编译执行，否则退化为基于 BFS 的同步顺序执行，保证无 langgraph 依赖也能运行。
- 依赖方向单向指向 `resolveagent` 核心（`fta`、`code_analysis`、`skills`、`agent.base`），不反向被核心引用；`__init__.py` 通过 `TYPE_CHECKING` + `__getattr__` 实现懒导入，避免强制加载可选依赖。
