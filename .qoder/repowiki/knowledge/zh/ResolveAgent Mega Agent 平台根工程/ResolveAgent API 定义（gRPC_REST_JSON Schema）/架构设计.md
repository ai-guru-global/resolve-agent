本模块为纯契约层，不包含业务逻辑，按协议类型分目录组织：
- `api/proto/resolveagent/v1/`：基于 proto3 的 gRPC 服务定义，统一使用 `package resolveagent.v1` 并通过 `option go_package = "github.com/ai-guru-global/resolve-agent/pkg/api/resolveagent/v1;resolveagentv1"` 指定 Go 生成路径；`common.proto` 提供跨领域共享的 `ResourceMeta`、`PaginationRequest/Response`、`ErrorDetail`、`ResourceStatus` 等基础消息，其他领域文件（`agent.proto`、`skill.proto`、`workflow.proto`、`rag.proto`、`registry.proto`、`selector.proto`、`platform.proto`）通过 import 引用这些公共类型，形成清晰的依赖方向。
- `api/openapi/v1/resolveagent.yaml`：OpenAPI 3.1.0 文档，描述 `/healthz`、`/readyz` 以及 `/api/v1/{agents,skills,workflows,models}` 等 REST 端点，作为 HTTP 接口的独立契约。
- `api/jsonschema/skill-manifest.schema.json`：基于 JSON Schema Draft 2020-12 的 Skill Manifest 校验规则，约束技能包的 `name`、`version`、`entry_point`、`permissions`、`scenario` 等字段。
- `third_party/protobuf/.gitkeep`：占位符，表明第三方 protobuf 依赖由外部管理。
各协议之间通过语义对齐（如 Agent/Skill/Workflow 在 proto 与 OpenAPI 中对应同一资源），但彼此独立维护，便于分别用于 gRPC 代码生成与 REST 文档/客户端生成。
