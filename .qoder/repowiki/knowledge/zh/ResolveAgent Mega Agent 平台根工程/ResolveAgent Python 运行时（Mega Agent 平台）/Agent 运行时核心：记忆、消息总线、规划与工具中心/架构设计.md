本模块由五个相互协作的运行时子组件构成，均位于 `python/src/resolveagent/` 下，彼此通过数据类与回调接口松耦合：
- `memory.py`：实现三层记忆架构——进程内 `WorkingMemory`（基于 `collections.deque` + `asyncio.Lock` 的滚动窗口）、Redis-backed `EpisodicMemoryClient`（按 session 持久化并支持语义摘要压缩）、Milvus RAG 向量库 `LongTermMemoryClient`（仅 importance≥0.7 沉淀），由 `HierarchicalMemory` 统一编排 connect/close/add/search/promote。
- `message_bus.py`：基于 `asyncio.Queue` + worker task 的订阅-发布总线 `AgentMessageBus`，支持 channel 订阅、可选 filter_fn、请求-响应模式（通过 `correlation_id` + `asyncio.Future`）；`MessageBusRegistry` 以 `asyncio.Lock` 管理多 bus 实例生命周期。
- `planning.py`：`HybridPlanner` 支持 REACTIVE（单步 ReAct）与 DELIBERATIVE（LLM 辅助子目标分解 + replan）两种模式，`Plan`/`PlanStep`/`ExecutionResult` 为状态载体；`ReActExecutor` 实现思考-行动循环，依赖外部 `resolveagent.llm.provider.ChatMessage` 进行推理。
- `resilience.py`：提供横切可靠性原语——三态 `CircuitBreaker`（CLOSED/OPEN/HALF_OPEN，带失败计数与 reset_timeout）和 `FallbackCascade`（顺序尝试多个策略，并可组合 circuit breaker）。
- `toolhub.py`：工具生态中枢——`ToolSchema`/`ToolRegistration` 描述工具契约，`CapabilityMap` 做能力索引与关键词匹配，`SchemaRegistry` 维护版本，`SecurityPolicy` 实施 PUBLIC/SENSITIVE/RESTRICTED 三级权限与审计，`DiscoveryService` 从 MCP 或本地定义自动发现并注册，最终由 `ToolHub` 统一暴露 find/can_use/execute/list 接口。
依赖方向：上层 agent 编排调用 planning → toolhub → memory/message_bus，resilience 作为装饰器式横切层被各组件复用；所有外部依赖（redis.asyncio、pymilvus、resolveagent.llm）均采用延迟 import，保证在无对应服务时仍可初始化。
