### ResolveAgent
- 定义：面向问题解决（Troubleshooting & Resolution）的生产级 AIOps 智能体平台，核心能力包括 Intelligent Selector 智能路由、Hybrid Planner 混合规划、Hierarchical Memory 三层记忆、FTA 故障树分析引擎、ToolHub 工具集、Resilience 熔断降级、Loop Engineering 反馈闭环等十二大架构特性。
- 别名：RA、resolve-agent

### Intelligent Selector
- 定义：三阶段元路由组件：意图分析 → 上下文增强 → 路由决策，支持 rule/llm/hybrid 三种策略，配合 Decision Audit Logger 和 Resilient Selector 实现自适应权重调整与错误分类路由偏好。
- 别名：selector、智能选择器、智能路由

### Hybrid Planner
- 定义：REACTIVE（ReAct 即时响应）与 DELIBERATIVE（计划分解）双模式规划器，由 Selector 决定采用哪种模式处理任务；deliberative 模式通过 LLM 结构化输出 + 规则模板回退实现目标分解。
- 别名：planner、混合规划器

### Hierarchical Memory
- 定义：三层记忆架构：Working Memory（进程内 deque 滚动窗口，max_size=20）、Episodic Memory（Redis TTL 过期）、Long-term Memory（Milvus/Qdrant 向量库 LRU 逐出），配合已解决问题沉淀与 RAG 双写实现故障经验复用。
- 别名：memory、分层记忆、三层记忆

### FTA 引擎
- 定义：故障树分析引擎，支持 AND/OR/NOT/VOTING/INHIBIT/PRIORITY_AND 六种门类型、最小割集计算、蒙特卡洛仿真，是 ResolveAgent 区别于通用 Agent 框架的核心护城河能力，用于 AIOps 场景的结构化根因诊断。
- 别名：FTA、故障树分析、fta-engine

### ToolHub
- 定义：工具发现、Schema 注册、Capability 映射与安全审计的统一工具集管理器，被 AgentHarness 封装后供各执行路径调用。
- 别名：toolhub、工具中心

### Resilience
- 定义：熔断降级体系：CircuitBreaker 三态机（Closed→Open→HalfOpen→Closed，threshold=5, recovery=30s）+ FallbackCascade 多级降级链（MCP→Native→LLM→Cached），确保诊断服务本身不挂。
- 别名：resilience、熔断降级、容错

### Loop Engineering
- 定义：Observe-Orient-Decide-Act (OODA) 持续反馈闭环：Go 侧 pkg/feedback 实现外环（信号收集→环形缓冲→聚合→告警→权重调整），Python 侧通过 FeedbackEmitter 上报执行结果，驱动 Selector 自适应权重。
- 别名：loop、反馈闭环、OODA

### AgentHarness
- 定义：统一执行器框架，收口 hooks/toolhub/sandbox/resilience 等散件，对外暴露 `run(task, agent_spec)` 接口，持有 context_manager、memory、tool_executor、hook_runner、resilience 五个槽位，是后续 Graph/Loop/Context/Memory 扩展的挂载点。
- 别名：harness、执行器框架

### GraphEngine
- 定义：图状工作流引擎（LangGraph 风格但不引入依赖），节点类型包括 agent/skill/fta_eval/rag_query/condition/human_gate，State 快照持久化至 PostgreSQL，SSE 按节点粒度推送事件，复杂请求可由 Selector 路由到预定义图或由 Planner 生成图。
- 别名：graph、图引擎、工作流引擎

### ContextManager
- 定义：统一上下文管理系统，承担 token 预算分配（system/memory/rag/history/tools 配额）、分层组装管线（SystemLayer→MemoryLayer→RAGLayer→HistoryLayer→TaskLayer）、压缩（compaction）三大职责，解决长时 AIOps 诊断会话的上下文窗口问题。
- 别名：context、上下文管理、token plan

### MemoryProvider
- 定义：记忆系统抽象协议，定义 add/search/consolidate/forget 接口，现有 NativeMemoryProvider 为默认实现，后续可扩展 Mem0/Zep/Letta 等外部记忆系统适配器，Go 侧 MemoryRegistry 保留为元数据与审计层。
- 别名：memory-provider、记忆提供者

### FeedbackEmitter
- 定义：Python 侧反馈上报组件，在 Harness 的 post_step/on_error hook 中将执行结果（成功率、耗时、路由命中、降级次数）以 FeedbackSignal 格式经 HTTP 上报给 Go collector，接通 Loop Engineering 外环形成自适应闭环。
- 别名：feedback-emitter、反馈发射器

### AdaptiveWeightAdjuster
- 定义：基于反馈的路由权重动态调整器，结合成功率驱动权重更新与时间衰减（0.95），使 Selector 从静态策略升级为自适应策略，是 Loop Engineering 闭环的关键组件。
- 别名：权重调整器、自适应权重

### Decision Audit Logger
- 定义：完整路由决策审计追踪组件，异步写入不阻塞主流程，记录 decision_type、confidence、reasoning、context_snapshot、latency_ms，支持持久化到 Go Platform Store，用于回溯路由依据。
- 别名：审计日志、audit-logger
