模块由 `runtime/` 和 `agent/` 两个子包组成，形成“接入层 → 执行引擎 → Agent/子系统”的分层结构：
- 接入层：`http_server.py` 基于 FastAPI + Uvicorn 暴露 `/v1/agents/{id}/execute`、`/v1/workflows/{id}/execute`、`/v1/rag/*`、`/v1/skills/*`、`/v1/code-analysis/*` 等 REST 端点，统一通过 SSE (`text/event-stream`) 返回事件流；`server.py` 提供 gRPC 入口（`AgentExecutionServer` / `AgentExecutionServicer`），在缺少 protobuf stubs 时回退到 aiohttp HTTP 实现；`__main__.py` 是 `python -m resolveagent.runtime` 的启动入口，读取 `RESOLVEAGENT_RUNTIME_HOST/PORT` 环境变量。
- 执行引擎：`engine.ExecutionEngine` 维护 agent pool、conversation history、hook runner、MCP adapter 与 `IntelligentSelector`，`execute()` 生成 `execution.started/selector.*/*completed/execution.*` 事件流，按 `RouteDecision.route_type`（direct/rag/skill/workflow/code_analysis/multi）分派到 `_stream_direct_llm`、`_stream_rag`、`execute_workflow` 等路径；`context.ExecutionContext` 用 dataclass 封装单次执行的 execution_id、conversation_id、trace_id 等上下文。
- 生命周期与注册表：`lifecycle.AgentPool` 基于 `OrderedDict` 实现 LRU 淘汰，`AgentLifecycleManager` 负责初始化/关闭；`registry_client.RegistryClient` 通过 httpx 访问 Go 平台的 `/api/v1/...` REST API，对 agent/skill/model/workflow/rag collection 做本地缓存并支持 `watch_registry` 占位流。
- Agent 层：`agent/base.BaseAgent` 定义最小接口（`reply`/`add_memory`/`reset`），`agent/mega.MegaAgent` 继承 BaseAgent 并持有 Lazy 初始化的 selector、LLM provider、RAG pipeline、SkillExecutor、FTA/Code/Traffic 分析引擎，按 route_type 分派到对应 `_execute_*` 方法；`agent/memory.py`、`agent/message.py` 提供消息与内存辅助。
依赖方向单向：HTTP/gRPC → ExecutionEngine → MegaAgent → 各子系统（llm/rag/skills/fta/traffic/code_analysis），并通过 `resolveagent.selector` 解耦路由决策。
