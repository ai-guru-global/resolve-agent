模块按职责分层组织：
- 入口层：`main.tsx` 通过 `@tanstack/react-query` 的 `QueryClientProvider` 和 `react-router-dom` 的 `BrowserRouter` 包裹根组件；`App.tsx` 集中声明所有页面路由并使用 `React.lazy` + `Suspense` 实现代码分割。
- API 抽象层：`api/client.ts` 暴露单一 `api` 对象，内部以 `request<T>` 封装 `fetch`，并通过 `Proxy` 动态拦截方法调用，在开发环境下优先尝试 `../mocks/codeAnalysis/*` 的局部 mock，再回退到 `./mock` 中的 legacy mock，最后才调用真实后端 `/api/v1/*`；后端可用性通过 `/health` 探测并缓存 30 秒。
- 数据获取层：`hooks/` 下每个文件对应一个业务域（agents/skills/workflows/rag/dashboard/settings），统一基于 `useQuery`/`useMutation` 组合 `api.*` 方法，使用字符串数组作为 `queryKey` 并配合 `invalidateQueries` 做写后失效。
- 状态管理层：`stores/app.ts` 使用 Zustand + `persist` middleware 持久化 sidebar/theme 等 UI 状态到 localStorage，key 为 `resolve-agent-ui`。
- 类型与常量：`types/index.ts` 集中定义 Agent/Skill/Workflow/RAG/FTA/Dashboard/Ops 等全部领域类型；`constants/index.ts` 导出 API_BASE_URL、枚举常量；`utils/index.ts` 提供 formatDate/truncate/debounce/shortId/safeJsonParse 等纯函数工具。
- 领域库：`lib/ragCorpusGenerator.ts` 是纯前端 RAG 语料生成器，将 K8s 调用链分析结果转换为多类文档（overview/source_file/function/flow/cross_reference/qa_pair/daily_ops/deep_troubleshoot/incident_response/testing/architecture/feature_consulting/product_learning），与后端 `CallChainRAGGenerator` 逻辑镜像对齐。
依赖方向单向：hooks → api → types；stores 独立不依赖 api；lib/utils/constants 被上层消费但不反向依赖。
