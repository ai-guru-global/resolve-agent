- 每个导入器类在 `__init__` 中通过可选参数注入下游客户端（pipeline/client/engine），便于测试时替换为 mock。
- 所有异步导入方法统一接受 `CorpusConfig` 与 `ProgressTracker`，并在处理单个文件时调用 `progress.file_processed` / `progress.file_error` 上报事件。
- 文件扫描遵循 `config.is_excluded()` 过滤，并结合内置跳过集合（如 `topic-skills` 下的 readme/enhancement-record/skill-schema）。
- chunking 策略由 `CorpusConfig.get_chunking_strategy` 根据文件路径模式动态选择（by_h2/by_h3/by_section/sentence/full_doc），不同导入器据此传入对应 strategy 与 chunk_size。
- 对外暴露的数据模型统一使用 `dataclass` 定义（如 `CorpusImportRequest`、`CorpusImportResult`、`SourceConfig`、`ImportStats`、`ProgressEvent`）。
- 错误处理采用 try/except 包裹单文件解析与外部调用，记录 warning 日志并通过 `ProgressTracker` 累计 errors，不中断整体流程。
