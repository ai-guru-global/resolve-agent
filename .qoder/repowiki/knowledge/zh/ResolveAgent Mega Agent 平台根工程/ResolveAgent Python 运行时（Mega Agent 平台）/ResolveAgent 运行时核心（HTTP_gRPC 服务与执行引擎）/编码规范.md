- 所有对外执行入口（engine.execute、engine.execute_workflow、HTTP 路由）均以 async generator 形式产出统一格式的 dict 事件流，包含 `type=content|content_chunk|event|error` 字段，SSE 层统一包装为 `data: {json}\n\n` 并以 `[DONE]` 结束。
- 外部子系统（LLM、RAG、Skills、FTA、Traffic、CodeAnalysis）采用延迟导入（函数体内 `from ... import ...`），避免循环依赖与冷启动开销。
- 路由分派集中在单一 switch-like 方法（`_execute_by_route`、`_streaming` 中的 `if decision.route_type == ...`），新增 route_type 只需追加分支并实现对应 `_execute_*` 方法。
- 错误处理统一通过 `_classify_exception` 映射为标准 `error_code`/`category`，并在异常分支 yield `type=event, event.type=execution.failed/workflow.failed` 事件后附带 content 兜底。
- 可插拔组件（registry_client、memory_client、hook_runner、mcp_adapter）以可选参数注入 ExecutionEngine，未配置时优雅跳过而非抛错。
- 全局单例通过模块级 `_xxx: T | None = None` 配合 `get_xxx()` 工厂函数暴露（如 `_runtime_server`、`_registry_client`），便于测试替换。
