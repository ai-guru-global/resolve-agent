## 1. 系统/方法概述

ResolveAgent 在 Go 平台层定义了一套统一的错误类型与错误码（`pkg/errors`），并通过 HTTP 中间件、处理器和 Python 运行时之间的映射，将 Go 侧的 `errors.Code` 与 Python 侧的异常分类进行双向对齐，形成跨语言的错误处理链路。

- Go 侧：集中式 `*errors.Error` 结构体 + 字符串枚举 `Code` + 标准哨兵错误 + `HTTPStatus` 映射。
- Python 侧：FastAPI 运行时通过 `_EXCEPTION_TO_CODE` 字典把内置异常分类为与 Go 一致的 `error_code`（如 `INVALID_ARGUMENT`、`NOT_FOUND`、`TIMEOUT` 等）。
- 网关/平台侧：`pkg/server/error_mapping.go` 将 Python 返回的 `error_code` 字符串再映射回 Go 的 `errors.Code`，从而让上层 handler 能按统一语义写出响应。

该仓库中未发现使用 `panic/recover` 作为常规错误控制流；Go 代码未出现 `panic(` 调用，Python 侧也未见全局 recover 策略。错误主要通过返回值、结构化 `Error` 对象或 FastAPI 的 `HTTPException` 传播。

## 2. 关键文件与包

- `pkg/errors/errors.go`：定义 `Code` 枚举、`Error` 结构体、哨兵错误、构造器（`New`/`Wrap`/`Newf`/`Wrapf`）、便捷构造器（`NotFound`/`AlreadyExists`/`InvalidArgument`）以及 `HTTPStatus` 状态码映射。
- `pkg/server/error_mapping.go`：`mapPythonErrorCode` 把 Python 返回的 `error_code` 字符串映射到 `errors.Code`，未知值默认降级为 `CodeInternal`。
- `pkg/server/response.go`：`writeJSON` / `writeError` 两个轻量 helper，用于向客户端输出 JSON 错误体 `{"error": message}`。
- `pkg/server/middleware/logging.go`：记录每个请求的 method/path/status/duration，便于追踪错误路径。
- `pkg/server/middleware/auth.go`：认证失败时直接写 `401 Unauthorized`，并将认证上下文注入 request context，供后续 handler 做权限判断。
- `python/src/resolveagent/runtime/http_server.py`：FastAPI 运行时，维护 `_EXCEPTION_TO_CODE` 异常→错误码映射表，提供 `_classify_exception` 与 `_build_error_event`，并在 SSE 事件流中统一产出 `{type: "error", error_code, category, message, trace_id}` 事件；同时包含自定义的 `RateLimitMiddleware`（429）与安全头中间件。
- `python/src/resolveagent/resilience.py`：Python 侧熔断器 `CircuitBreaker` 与 `FallbackCascade`，抛出专用 `CircuitOpenError`，并配合日志实现优雅降级。
- `pkg/circuitbreaker/breaker.go`：Go 侧熔断器，暴露哨兵错误 `ErrCircuitOpen`，与 Python 侧熔断概念对称。

## 3. 架构与约定

### 3.1 统一错误模型（Go）

`errors.Error` 包含三个字段：`Code`（机器可读的错误码）、`Message`（人类可读消息）、`Cause`（被包装的底层错误）。通过实现 `Unwrap()` 支持 `errors.Is`/`errors.As` 链式判断。所有业务错误应通过 `errors.New`/`errors.Wrap`/`errors.NotFound` 等工厂创建，而非裸 `fmt.Errorf`，以保证 `Code` 可被上层提取。

`HTTPStatus` 根据 `Code` 映射到 HTTP 状态码：`NOT_FOUND → 404`、`ALREADY_EXISTS → 409`、`INVALID_ARGUMENT → 400`、`UNAUTHORIZED → 401`、`FORBIDDEN → 403`、`UNAVAILABLE → 503`、`TIMEOUT → 504`、`CONFLICT → 409`、`RATE_LIMITED → 429`，其余默认 `500`。

### 3.2 处理器层的错误输出约定

各 handler（如 `agent_handlers.go`、`analysis_handlers.go`）普遍采用以下模式：解析失败 → `writeError(w, http.StatusBadRequest, ...)`；资源不存在 → `writeError(w, http.StatusNotFound, ...)`；下游执行失败 → `writeError(w, http.StatusInternalServerError, err.Error())`。当前 handler 层尚未统一通过 `errors.HTTPStatus(err)` 自动推导状态码，而是手写 HTTP 常量，但已具备向 `errors.Error` 收敛的条件。

### 3.3 跨语言错误码对齐

Python 运行时通过 `_EXCEPTION_TO_CODE` 将常见异常归类为与 Go 一致的错误码：
- `ValueError`/`TypeError` → `INVALID_ARGUMENT`
- `KeyError`/`FileNotFoundError` → `NOT_FOUND`
- `PermissionError` → `FORBIDDEN`
- `TimeoutError` → `TIMEOUT`
- `ConnectionError` → `UNAVAILABLE`
- `NotImplementedError` → `INTERNAL`

SSE 事件流中以 `{type:"error", error_code, category, message, trace_id}` 形式返回；Go 平台侧再通过 `mapPythonErrorCode` 还原为 `errors.Code`，使 Go 端能继续用 `errors.HTTPStatus` 生成响应。

### 3.4 中间件与鉴权错误

- `AuthMiddleware`：跳过 `/health`、`/ready`、`/metrics` 等健康检查路径；认证失败时记录 warn 日志并直接返回 `401`。
- `Logging` 中间件：捕获实际写入的 `statusCode`（通过包装 `ResponseWriter`），用于审计错误率。
- Python 侧 `RateLimitMiddleware`：基于滑动窗口实现 429 限流。

### 3.5 熔断与重试

- Go 侧 `pkg/circuitbreaker`：当断路器打开时返回 `ErrCircuitOpen` 哨兵错误，调用方可据此快速失败。
- Python 侧 `resilience.CircuitBreaker`：状态机 CLOSED/OPEN/HALF_OPEN，达到阈值后抛 `CircuitOpenError`；`FallbackCascade` 提供多策略回退，并以 `FallbackResult.success` 表达是否成功。

## 4. 约定与约束

- **错误必须带 Code**：业务错误应通过 `pkg/errors` 的 `New`/`Wrap`/`NotFound`/`InvalidArgument` 等工厂创建，确保 `Code` 字段存在，以便 `HTTPStatus` 正确映射。
- **禁止 panic 作为控制流**：全仓未发现 `panic(` 调用；错误应通过返回值或结构化错误向上冒泡。
- **Python 异常需显式分类**：新增异常类型应在 `_EXCEPTION_TO_CODE` 中注册对应 `error_code` 与 `category`，否则会被归入 `INTERNAL/unknown`。
- **Go 与 Python 错误码保持同构**：`mapPythonErrorCode` 是单一来源的映射表，新增错误码需同步更新 Go `errors.Code`、`HTTPStatus`、`mapPythonErrorCode` 三处。
- **鉴权失败走中间件**：认证相关错误由 `AuthMiddleware` 统一拦截并返回 `401`，handler 不应自行拼装鉴权错误。
- **SSE 错误事件格式固定**：Python 运行时产生的错误事件必须包含 `type`、`error_code`、`category`、`message`、`trace_id` 字段，供上游消费。
- **熔断错误可区分**：Go 侧使用 `ErrCircuitOpen` 哨兵错误，Python 侧使用 `CircuitOpenError`，调用方应分别检测以决定是否走 fallback。

综上，ResolveAgent 的错误处理以 `pkg/errors` 为中心，结合 Python 运行时的异常→错误码映射与 Go 平台的反向映射，实现了跨语言、可观测、可降级的一致错误语义。
