本模块按部署目标分层组织：
- `docker/`：三个多阶段 Dockerfile（`platform.Dockerfile`、`runtime.Dockerfile`、`webui.Dockerfile`）分别构建 Go 平台服务、Python 运行时与 React WebUI；`nginx.conf` + `default.conf` 作为 WebUI 反向代理；`deploy.sh` 是统一入口，封装 `docker compose` 命令并提供 `up/dev/deps/build/down/logs/status/clean` 子命令，自动检测依赖、生成 `.env` 并驱动 compose。
- `docker-compose/`：`docker-compose.yaml` 定义生产栈（platform/runtime/webui/postgres/redis/nats），通过 `depends_on` 与 healthcheck 保证启动顺序；`docker-compose.dev.yaml` 叠加开发热重载；`.env.example` 集中声明所有可配置项（端口、数据库、Redis、NATS、LLM Key、Gateway、Telemetry 等）。
- `helm/resolveagent/`：标准 Helm v2 Chart，`Chart.yaml` 描述应用元信息，`values.yaml` 暴露 platform/runtime/webui/ingress/postgresql/redis/nats 的可覆盖参数，`templates/` 下为 platform 与 runtime 各自的 Deployment/Service 模板。
- `k8s/`：Kustomize 根仅包含 `namespace.yaml`，用于在已有集群中创建命名空间。
依赖方向自顶向下：`deploy.sh` → docker-compose → Dockerfile；Helm/Kustomize 独立于 Compose，面向 Kubernetes 场景。
