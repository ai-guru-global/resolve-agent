本模块由多个相互独立、无内部依赖的 Go 子包组成，每个子包聚焦单一横切能力，被上层业务通过接口或函数调用复用：
- `pkg/config`：基于 spf13/viper 实现集中式配置加载，支持 YAML 文件 + 环境变量（前缀 RESOLVEAGENT，点号→下划线替换），并提供默认值与敏感字段校验。
- `pkg/errors`：定义统一错误类型 `Error`（含 Code、Message、Cause）、标准哨兵错误与 HTTP 状态码映射，向上层暴露 `errors.Is/As/New/Join` 别名以兼容标准库。
- `pkg/event`：定义 `Event` 数据结构与 `Bus` 接口（Publish/Subscribe/Close），并通过 `nats.go` 提供 NATS 后端实现，使事件发布订阅对上层透明。
- `pkg/health`：提供 `Checker` 聚合组件健康检查，输出 `/healthz`（liveness）与 `/readyz`（readiness）HTTP 处理器，并通过可选的 `FeedbackEmitter` 接口将状态变化反馈给外部观测系统。
- `pkg/logger`：基于 `log/slog` 封装带选项（级别、格式、输出、属性）的结构化日志器，支持组件作用域与 context 传播，并提供 `Nop` 用于测试禁用日志。
- `pkg/retry`：实现指数退避+抖动重试策略 `Policy`，通过 `RetryObserver` 接口回调成功/耗尽结果，便于接入反馈闭环。
- `pkg/service`：`RegistryService` 作为 gRPC 服务层，组合 agent/skill/workflow 注册表与 gateway ModelRouter，对外暴露查询与列表 API。
- `pkg/version`：通过 ldflags 注入 Version/Commit/BuildDate，提供 `Info()` 供 CLI/HTTP 端点展示。
依赖方向单向向下：service → registry/gateway；event → nats；其余包之间互不依赖，仅被上层应用组合使用。
